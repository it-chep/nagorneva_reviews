# Промпт для разработки админ-фронтенда

Ты — senior frontend-разработчик. Создай админ-панель управления отзывами врачей на React 18 + TypeScript, сохраняя принципы и удачные паттерны из проекта `/Users/maksimneceporuk/medblogers/medblogers_admin`: `entities`, `features`, `pages`, `shared`, Redux Toolkit, SCSS Modules, `ApiService`, переиспользуемые `MyInput`, `MyTextarea`, `Modal`, `ToggleSwitch`, `ConfirmationAction`, глобальный лоадер и глобальные сообщения. Не копируй старые сущности «freelancer» — адаптируй их под предметную область докторов и отзывов.

Backend base URL должен браться из `REACT_APP_API_URL`. Все админские запросы после логина отправляй с `Authorization: Bearer <access_token>`. Токен получай из `POST /api/v1/admin/login` с телом `{ "email", "password" }`; при 401 очищай сессию и перенаправляй на `/auth`.

Реализуй страницы и маршруты:

1. `/auth` — аккуратная форма email/пароль, состояния отправки и ошибок.
2. `/doctors` — таблица/список врачей с поиском по локально загруженным полям, фильтрами город/специальность/активность и кнопкой создания. Источник: `GET /api/v1/admin/doctors`, а справочники — `/cities` и `/specialties`.
3. `/doctors/:id` — ключевая страница. Вверху редактируемая карточка врача: публичное имя, полное ФИО, город, специальность, координаты, тумблер активности, тумблер согласия на обработку ПД, фото с предпросмотром. Файл отправляй как multipart на `POST /api/v1/admin/doctors/{id}/photo`; остальные изменения — `PATCH /api/v1/admin/doctors/{id}`. Покажи заметное пояснение: при выключенном согласии публичная карта скрывает фото и полное имя.
4. В карточке врача сделай отдельную секцию «Отзывы» с данными `GET /api/v1/admin/doctors/{id}/reviews`. Отзывы показывай таблицей: оценка (звёзды и число), курс, комментарий, дата, статус. В каждой строке — редактировать, скрыть/показать (это `PATCH` с `is_active`), удалить с обязательным подтверждением. Добавление отзыва — модальное окно с выбором курса, рейтингом 1–5, комментарием и активностью; `POST /api/v1/admin/reviews`. Обновление — `PATCH /api/v1/admin/reviews/{id}`, удаление — `DELETE /api/v1/admin/reviews/{id}`. После любой мутации обновляй только список отзывов врача, не весь экран.
5. `/dictionaries/cities`, `/dictionaries/specialties`, `/dictionaries/courses` — компактные CRUD-страницы с таблицей и modal-формой. Их endpoints соответствуют `/api/v1/admin/{cities,specialties,courses}`.
6. `/users` — минимальная страница для единственного администратора: список, смена email/пароля, без ролей и permissions.

Требования к UX: desktop-first, но без горизонтального скролла на 375px; skeleton/loading в таблицах; пустые состояния; toast для успешных операций и ошибок; диалоги удаления; отключение submit при незаполненных обязательных полях; число рейтинга проверяется в диапазоне 1–5. Не показывай пароль ни в таблицах, ни в состоянии приложения. Все API-типы опиши в `entities/*/model/types.ts`; HTTP-вызовы — в `entities/*/api/*Service.ts`; сложные операции вынеси в `features`. Поставь ссылки на конкретные компоненты/файлы, которые ты создаёшь, и приложи инструкцию запуска.
